# Remember RP Launcher — 0.1.0

Самостоятельный Windows-лаунчер Remember RP на Electron + React + TypeScript с интеграцией через официальный MiNT Launcher API (`Launcher.exe --api`).

## Что уже реализовано

- Красно-чёрный GTA RP интерфейс.
- Настройки пути к MiNT и GTA V, игрового имени.
- Запуск MiNT в скрытом API-режиме.
- JSON Lines обмен через stdin/stdout.
- Ожидание `ready`, команды `servers.list`, `prepare`, `launch`.
- Отображение событий прогресса.
- Обработка ошибок, таймаутов и `trust.required`.
- Локальное сохранение настроек в папке Electron userData.

## Требования

- Windows 10/11 x64.
- Node.js 20 LTS или новее (рекомендуется Node.js 22 LTS).
- npm.
- Установленный MiNT Multiplayer, версия с API (начиная с 0.6.0-dev).
- Лицензионная установленная GTA V для реального запуска игры.

## Установка проекта

1. Распакуй архив, например в `D:\\Projects\\mint-launcher`.
2. Открой PowerShell в этой папке.
3. Установи зависимости:

   ```powershell
   npm install
   ```

4. Запусти интерфейс в режиме разработки:

   ```powershell
   npm run dev
   ```

Приложение откроется даже без установленного MiNT. В таком случае интерфейс работает, но запуск/подготовка игры не выполняются.

## Установка MiNT

1. Открой официальный репозиторий релизов: https://github.com/DaVillka/mint-multiplayer-releases/releases
2. Выбери совместимый релиз MiNT Multiplayer с поддержкой Launcher API (0.6.0-dev или новее).
3. Скачивай клиент только из официального источника разработчика и следуй его инструкции установки.
4. Если установщик позволяет выбрать папку, используй `D:\\MiNT`.
5. Убедись, что в папке существует `D:\\MiNT\\Launcher.exe`. Если файл расположен иначе, укажи полный путь в настройках нашего лаунчера.
6. Установи/укажи путь к GTA V в настройках. Для первой проверки можно оставить поле пустым, если MiNT сам обнаруживает игру.

> MiNT сейчас распространяется как development/pre-release. Проверь требования конкретного релиза и совместимость с установленной сборкой GTA V. Не скачивай `Launcher.exe` с посторонних сайтов.

## Первый запуск и проверка API

1. Запусти наш лаунчер (`npm run dev`).
2. Нажми «Настройки» и проверь путь `D:\\MiNT\\Launcher.exe`.
3. Нажми «Проверить MiNT».
4. Лаунчер запустит `Launcher.exe --api` скрытно и дождётся JSON-события `ready`.
5. После готовности запросит список серверов.
6. Если сервер не появился в списке, введи его адрес вручную в формате `host:port`.
7. Нажми «Подготовить файлы» для проверки/загрузки ресурсов без запуска игры.
8. Нажми «Играть» для обновления MiNT, подготовки ресурсов и запуска GTA V.

## Важные ограничения стартовой версии

- Адрес сервера может быть введён вручную. Формат объектов из `servers.list` может меняться между версиями MiNT; адаптируй нормализацию под реальный ответ твоей сборки.
- MiNT выполняет одну операцию за раз. UI блокирует повторные игровые операции, пока предыдущая не завершилась.
- Поле «Новости» пока содержит демонстрационные записи. Backend, аккаунты, онлайн и админ-панель не подключены.
- Экран подключения внутри самой GTA не заменяется этим Electron-окном. Для его изменения нужно отдельно изучить поддерживаемые MiNT CEF/ресурсы клиента.
- В API `launch` успешный результат `handedOff` означает передачу управления игровому клиенту, а не подтверждение полного входа персонажа на сервер.
- Для production перед распространением добавь подпись установщика, проверку целостности обновлений, безопасную авторизацию и серверную конфигурацию.

## Автообнаружение GTA V

При первом запуске лаунчер автоматически ищет папку GTA V в:
- реестре Windows (Rockstar Games);
- стандартных и пользовательских библиотеках Steam;
- манифестах Epic Games Launcher;
- нескольких типовых папках на дисках C:, D:, E: и F:.

Папка считается найденной, если в ней есть `GTA5.exe`, `PlayGTAV.exe` или `GTA5_Enhanced.exe`.
Результат автоматически сохраняется в настройках. Если поиск не сработал, откройте «Настройки» и нажмите «Найти GTA V» или укажите путь вручную.

## Адрес сервера для разработки

Пока используется локальная заглушка `127.0.0.1:22005`. Это loopback-адрес текущего компьютера, а не публичный адрес сервера. Для подключения к удалённому серверу его нужно будет заменить в настройках.


## Важное ограничение MiNT API

MiNT может отвечать `BUSY: Wait for the current operation to finish`, если отправить `servers.list` во время обновления или подготовки ресурсов. Поэтому лаунчер не запрашивает список серверов автоматически при старте MiNT. Для единственного сервера адрес задаётся конфигурацией лаунчера, а онлайн и слоты следует получать из отдельного status/query endpoint игрового сервера.

## Автообновление Remember RP (GitHub — заглушка)

В проект добавлен механизм самообновления через **GitHub Releases** на базе `electron-updater`. Пока репозитория нет, функция намеренно отключена: в настройках отображается сообщение, что GitHub ещё не подключён. Лаунчер продолжает запускаться как обычно.

### Когда GitHub-репозиторий будет создан

1. Создай публичный репозиторий `remember-rp-launcher` на GitHub.
2. В `src/main/index.ts` в объекте `UPDATE_SOURCE` замени `YOUR_GITHUB_USERNAME` на свой GitHub username и установи `enabled: true`.
3. В `package.json` в `build.publish[0].owner` укажи тот же username. Поле `repo` должно совпадать с названием репозитория.
4. Подними `version` в `package.json` (например, `0.1.1`) перед каждым новым релизом.
5. Собери и опубликуй релиз командой `npm run release` из окружения, где задан `GH_TOKEN` с правом публикации Releases.
6. Для GitHub Actions вместо локального токена можно будет настроить публикацию через `GITHUB_TOKEN`.

`electron-builder` создаёт установщик NSIS и служебный `latest.yml`; эти файлы должны попасть в GitHub Release. `electron-updater` проверяет релизы при старте установленного лаунчера, а также по кнопке «Проверить обновления» в настройках. При обнаружении версии пользователь сможет скачать её, увидеть процент загрузки и перезапустить лаунчер для установки.

Важно: автообновление относится только к **Remember RP Launcher**. MiNT Multiplayer и GTA V этим механизмом не обновляются. Для первой установки и будущих обновлений нужен Windows NSIS installer, собранный тем же приложением.

### Текущая заглушка

- GitHub owner: `YOUR_GITHUB_USERNAME`
- GitHub repo: `remember-rp-launcher`
- Проверка релизов: отключена до создания репозитория
- UI в настройках: включён, показывает состояние заглушки


## Публикация обновлений через GitHub Releases

Автообновление использует `electron-updater`. Для каждой версии `electron-builder` должен опубликовать установщик, `latest.yml` и `.blockmap` в GitHub Release репозитория `ColinsBlares/launcher`. Не загружай `latest.yml` вручную и не переименовывай установщик.

### Первый релиз и следующие версии

1. Из-за лимита GitHub в 100 MB на отдельный файл runtime нельзя хранить обычными файлами в Git. Создай на GitHub отдельный Release с тегом `runtime-assets`, отметь его как **Pre-release** и прикрепи asset `mint-runtime.zip`. Внутри архива должна быть папка `client`, а в ней `Launcher.exe`, DLL и все ресурсы MiNT. Этот pre-release не будет выбран как последняя стабильная версия лаунчера.
2. Измени `version` в `package.json` на следующий номер (сейчас проект подготовлен к `0.1.1`).
3. Закоммить и отправь изменения в `main`.
4. Создай и отправь тег, совпадающий с версией: `git tag v0.1.1` и `git push origin v0.1.1`.
5. GitHub Actions скачает `mint-runtime.zip` из pre-release `runtime-assets`, распакует его и проверит наличие `client/Launcher.exe`. Затем выполнит Windows-сборку и опубликует Release с установщиком и автоматически сгенерированным `latest.yml`.
6. Проверь страницу https://github.com/ColinsBlares/launcher/releases и убедись, что в Assets есть `.exe`, `latest.yml` и `.blockmap`.

### Обязательные настройки GitHub

В Settings → Actions → General → Workflow permissions должно быть разрешено `Read and write permissions`, если настройки репозитория не наследуют права workflow. Workflow также объявляет `contents: write`.

### Проверка обновления

Установленная версия лаунчера вызывает `autoUpdater.checkForUpdates()`. Если опубликована версия новее текущей, появляется кнопка скачивания; после загрузки — кнопка перезапуска и установки. В режиме разработки проверка отключена. Первый установщик нужно собрать и установить отдельно; автообновление работает только после установки приложения.
